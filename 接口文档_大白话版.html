一、先搞懂 3 个词

1. 接口（API）是什么？
就是服务员。你在手机上点了"记一笔账"，手机不会自己存数据，它会把这件事交给服务员，服务员再送到后厨（数据库）。
每个"能办的事"就是一个接口。这个系统有 15 个接口 = 15 个前台窗口。
2. 请求（Request）和响应（Response）
你对着窗口说"我要记账，金额 100，分类 food" → 这叫请求。
窗口回你"办好了，编号是 7" → 这叫响应。
请求由三样东西组成：地址（哪个窗口）、方法（办什么事）、内容（要什么材料）。
3. 四个"方法"（动词）
方法大白话对应生活
GET我要看查余额
POST我要新建新开一张卡
PUT我要改改手机号
DELETE我要删销户
所以 GET /transactions 读作"我要看交易列表"，DELETE /transactions/7 读作"我要删掉编号 7 的那笔交易"。
4. 状态码：服务员的脸色
每次响应都会带一个三位数字，告诉你事情办成没办成：
码意思你该怎么办
200办好了看返回的内容
201新建成功了看返回的新对象
400你要求的事办不了（业务上不允许）看 detail 里怎么说
401你没出示通行证 / 通行证是假的去登录拿 token
404你要的东西不存在（或不是你的）检查编号
422你填的格式不对（少字段、太短、类型错）看 detail 数组里指了哪个字段
500后厨炸了（服务器内部错误）这是 bug，要提缺陷单
5. token（通行证）是什么？
注册/登录之后，系统发给你一串很长的字符，长得像
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIn0.abc123
它被两个点分成三段。以后你每次办事，都要在请求头里带上它：
Authorization: Bearer eyJhbGciOi...
它证明"你是谁"。没有它，除了注册和登录，别的接口一律回你 401。

二、这个系统一共能干什么

一句话：它是个记账本。三个东西：用户、交易、预算；统计是现算的，不用存。

① 新用户注册　　　　POST /register　　邮箱 + 密码
　　　↓
② 登录拿通行证　　　POST /login　　　 返回 token
　　　↓
③ 记一笔账　　　　　POST /transactions　金额 100、分类 food
　　　↓
④ 查我记了哪些　　　GET /transactions　 可按分类/金额/月份筛
　　　↓
⑤ 看这个月花多少　　GET /stats　　　 总支出、笔数、最大单笔
　　　↓
⑥ 设个限额管自己　　POST /budgets　　 "餐饮每月最多 1500"

再加上"单独查 / 改 / 删"某一笔 → 就是全部 15 个接口了。
一个重要认知：统计（/stats）没有自己的数据表，它是每次现算的——把这月的交易金额加起来。 所以"删掉一笔交易，统计会自动变少"，而"预算"和"交易"在这个系统里毫无关联（设了 1500 的预算，系统不会告诉你已经花了多少）。这是它的产品短板，也是你写测试报告时的素材。

GET /transactions 要通行证
用户想干什么
看看我记过哪些账，可以按条件筛

会失败的情况

⚠ 这里有个真缺陷（你写测试报告能写进去）
项目 README 上写着支持 max_amount、start_date、end_date 三个参数， 但代码里根本没实现。而且 FastAPI 会把不认识的多余参数悄悄忽略—— 所以你传 ?max_amount=200，它不会报错，而是把全部数据都还给你。
这就是最危险的"假成功"：你以为筛过了，其实没筛。对应用例 TRX-048~050。

四、状态码速查

码什么时候出现返回长什么样
200查询/更新/删除成功业务数据
201注册、建交易、建预算成功新建出来的对象
400业务规则不允许：邮箱重复、sort 非法、month 格式错{"detail":"一句话说明"}
401没带 token（Not authenticated）／token 无效（Invalid token）／账号密码错（Invalid credentials）{"detail":"..."}
404编号不存在，或东西是别人的{"detail":"... not found"}
422字段格式不对{"detail":[{"type","loc","msg","input"}]}
500服务器崩了一般没有规范结构 → 提缺陷
400 和 422 的区别（最容易混）：
422 = 电脑在挑你毛病："你这个字段类型/长度不对"（发生在业务逻辑执行之前，框架自动拦）。
400 = 人在挑你毛病："你要求的事业务上办不了"（比如这邮箱已经有人用了，代码里手动抛的）。

五、我自己怎么发一个请求试试

三种方式，从简单到正式：

方式 1：用 PowerShell（Windows 自带，最省事）

# 探活
Invoke-RestMethod -Uri "http://127.0.0.1:8000/"

# 注册
$body = @{ email = "try01@example.com"; password = "Passw0rd!23" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/register" -Method Post -Body $body -ContentType "application/json"

# 登录拿 token
$login = @{ email = "try01@example.com"; password = "Passw0rd!23" } | ConvertTo-Json
$token = (Invoke-RestMethod -Uri "http://127.0.0.1:8000/login" -Method Post -Body $login -ContentType "application/json").access_token

# 带 token 记一笔
$h = @{ Authorization = "Bearer $token" }
$trx = @{ amount = 100; category = "food" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/transactions" -Method Post -Headers $h -Body $trx -ContentType "application/json"

方式 2：用 Python（就是你写测试用的那个）

import requests

BASE = "http://127.0.0.1:8000"
r = requests.post(f"{BASE}/login", json={"email": "try01@example.com", "password": "Passw0rd!23"})
token = r.json()["access_token"]

r = requests.post(f"{BASE}/transactions",
                  json={"amount": 100, "category": "food"},
                  headers={"Authorization": f"Bearer {token}"})
print(r.status_code, r.json())
